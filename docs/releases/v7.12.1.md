# TokenSave v7.12.1

Source release: <https://github.com/aovestdipaperino/tokensave/releases/tag/v7.12.1>

**Use this instead of v7.12.0.** Same code; v7.12.0's release pipeline failed and left it missing its Windows x64 asset, macOS bottle, `SHA256SUMS` and crates.io publish.

The feature content of this release is v7.12.0's — release integrity, a layout-independent resolution metric, a git hook that can finally update itself, and two MCP fixes. Full detail in [CHANGELOG.md](https://github.com/aovestdipaperino/tokensave/blob/master/CHANGELOG.md).

## `upgrade` now verifies what it downloads (#525)

Integrity previously rested entirely on TLS to GitHub and on the release pipeline not being compromised. Releases now publish a `SHA256SUMS` asset and `upgrade` verifies the archive **before extraction**.

It **fails closed**: a release with no sums file, or one that does not name your platform's asset, aborts rather than installing unverified. Skipping the check when the file is merely missing would hand anyone able to suppress one small file an unverified install, which is the whole thing the check exists to prevent.

Two limits stated plainly: **this release cannot be verified by the binary upgrading into it**, since your installed 7.11.x predates the checking code — verification starts biting from the next release. And checksums served from the same origin as the artifact are not a signature; they do not vouch for the release pipeline itself.

## `tokensave audit-edges` (#536)

A new command measuring bare-name resolution quality without depending on how a project arranges its directories.

The metric it replaces counted edges crossing from production into `tests/`, which cannot see a phantom whose two ends are both production code. Measured against its own parent, #533 removed **1,216** edges on a 515-file Python project while that metric saw **731** — so a change with close to 100% precision read as 60%.

Read the headline figure comparatively: index two commits, diff them. The "most-collided targets" list is usually the more actionable half — a short name on a nested helper (`p`, `total`, `files`) becomes the sole candidate for every stray reference to it in the project.

## The `post-checkout` hook can update itself (#342)

The installer skipped a hook that already carried tokensave's marker, and the writer only ever appended — so a change to the hook body never reached anyone who had already installed. tokensave now rewrites only the region between its own markers: **everything outside the fence is preserved byte-for-byte**, the write is atomic, and the file mode is carried over.

The snippet is now a single delegating line, so this is the last time the file needs rewriting; later changes to hook behaviour ship with the binary.

**This is why 7.12.x is a minor bump rather than a patch** — the silent reinstall a minor transition triggers is what delivers the rewrite to existing installs. No action needed on your part.

⚠️ **Downgrading below 7.12.0 leaves the hook inert** until a later install rewrites it. It fails silently rather than breaking `git checkout`.

## MCP fixes

**A slow pre-dispatch resync can no longer stall a tool call past the client's deadline (#535).** The staleness resync ran inline and unbounded at the head of every `tools/call`; a client that disables a server on timeout lost tokensave for the session. The *wait* is now bounded (5 s, `TOKENSAVE_AUTOSYNC_BUDGET_MS` to change, `0` for the old behaviour) while the work itself is never dropped mid-write. The stderr log was the more misleading half: a call hanging in the pre-dispatch gates printed nothing, so the tail named the previous, unrelated tool.

**The handshake now negotiates the protocol version** instead of always answering `2024-11-05`. A host pinning a newer revision and validating strictly could treat that as an unagreed downgrade and drop the connection before `tools/list`, surfacing as a bare "MCP server failed to connect".

**The rules file `install` writes now names `tokensave_read` (#540)** — agents route the tools the file names, and it listed every navigation tool but not that one.

## Pipeline fixes specific to 7.12.1

`sha256sum` does not exist on macOS, which is what failed v7.12.0's macOS leg; it now falls back to `shasum -a 256`. And the Homebrew tap is no longer updated when a build leg failed — v7.12.0 published a formula with an empty `arm64_sonoma` hash that Homebrew could not install against.
